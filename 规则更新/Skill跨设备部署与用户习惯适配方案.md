# Skill 跨设备部署与用户习惯适配方案

> 版本：v1.0　制定日期：2026-08-20　状态：执行中
> 配套：`多Agent协作_Skill文件输出管理方案.md`（多 Agent 输出规范）、`UCS_命名流程规范.md`（命名规则）

---

## 一、两个问题

### 问题 A：每台电脑的路径不一致

当前 skill（`SKILL.md`、`references/naming-rules.md`）内写死了 `D:\Ai_Project\UCS\` 这类绝对路径。换一台电脑、换一个账号，路径就失效，Agent 找不到清单目录与日志目录，流程直接断掉。

### 问题 B：每个人命名习惯不同

不同用户/不同 Agent 的命名习惯各异：清单命名、日志命名、目录叫法、中文关键词分隔符（全角逗号 / 斜杠 / 空格）、是否保留 CatID 前缀、文件夹翻译风格……skill 写死一种风格，别人用不惯，就会各自改、各自造，传播后又形成新的「方言」，与 A 问题叠加造成口径全面分叉。

**核心思路：skill 逻辑与用户环境解耦——路径不假设、习惯不写死，全部收敛为「启动探测 + 本地配置」两步。**

---

## 二、问题 A 方案：路径零假设 + 启动探测协议

### 2.1 原则

skill 内部**一律不写绝对路径**。所有路径引用改用占位符 `<UCS_ROOT>`，由 Agent 在每次会话开始时按下面协议定位真实根目录。

### 2.2 探测协议（SKILL.md 第一步必做）

Agent 按顺序探测，命中即停：

1. **环境变量** `UCS_ROOT`（最可靠，推荐首选）
   - 首次配置时由部署引导写入系统环境变量，所有平台（Windows / macOS / Linux）通用
   - Agent 启动即读取，零歧义
2. **当前工作区自检**：当前目录或其父目录是否直接含 `命名清单 / 日志 / 规则更新` 三个子目录
   - 在项目根目录打开 AI 时自动命中，无需任何配置
3. **常见位置扫描**：依次检查 `D:\Ai_Project\UCS`、`~/UCS`、`~/Documents/UCS`
   - 兜底用，命中即采用
4. **以上均未命中 → 询问用户**：请用户给出根目录，并引导完成首次部署（写环境变量 / 建三目录），一次配置，长期有效

### 2.3 配套：`install.md` 部署引导（随 skill 分发）

每台新电脑首次安装 skill 时执行一次：

```
1. 建目录（可按用户习惯改名，见问题 B）
   命名清单/  日志/  规则更新/
2. 配置环境变量 UCS_ROOT=<你的根目录>
   Windows:  setx UCS_ROOT "D:\Ai_Project\UCS"
   macOS:    echo 'export UCS_ROOT=~/UCS' >> ~/.zshrc
   Linux:    同上写入 ~/.bashrc
3. 复制 ucs-config.local.json（见问题 B），按自己习惯修改
4. 自检：让 Agent 执行「定位工作根目录」，确认命中后再开始
```

## 三、问题 B 方案：配置化（ucs-config 机制）

### 3.1 配置分层

| 层级 | 文件 | 说明 |
|---|---|---|
| 标准默认 | `ucs-config.default.json` | skill 内置，**不可修改**，用于校验与兜底 |
| 本地覆盖 | `ucs-config.local.json` | 每台电脑/每位用户自己的，**不参与 skill 同步**，缺失时用默认 |

Agent 输出时：**读取 local → 缺失项回退 default**。skill 逻辑本身不变，习惯差异全部收敛到一份本地文件。

### 3.2 配置项一览（default 值 = 当前 WorkBuddy 标准）

| 配置项 | default（标准模式） | 可自定义方向 |
|---|---|---|
| 根目录 | 无（走探测协议） | 由环境变量/本地配置指定 |
| 目录结构 | `命名清单 / 日志 / 规则更新` | 目录名可全自定义 |
| 清单命名 | `UCS_命名清单_<Agent>_<库名>.txt` | 前缀、分隔符、后缀可改 |
| 清单格式 | .txt 双列（原文件名<TAB>翻译后文件名） | 可改 .md 表格（注：重命名脚本只认双列 txt） |
| 日志命名 | `<Agent>_YYYY-MM-DD.md` | 命名模板可改 |
| 中文关键词 | `【（分类）关键词1，关键词2】` | 是否带分类括号、分隔符（，/ /） |
| CatID 前缀 | 插入在英文名前（如 `AMBBird_<原名>`） | 保留 / 去掉 |
| 文件夹翻译 | `【中文翻译】英文原名` | 风格模板 |
| 附带文件处理 | 删除（.txt/.pdf/.jpg/.png/.html/.htm/.md/README） | 删除 / 跳过 / 归档 |

> **红线**：`ucs-zh-en.tsv` 对照表、`known-conflicts.md` 矛盾裁决、UCS CatID 分类本体不可配置——这是命名正确性的根基，个人习惯只能在「展示格式」层面自定义，不能改「分类本体」。

### 3.3 与多 Agent 方案的衔接

- 本方案解决「跨设备、跨人」的适配；`多Agent协作_Skill文件输出管理方案.md` 解决「同一项目内多 Agent」的统一归档
- **本地配置只管自己怎么干活；一旦产出文件提交到共享根目录，必须服从统一归档规范**（清单命名/日志命名/双列格式），否则共享区又会乱
- 即：**个性化工作，标准化提交**
