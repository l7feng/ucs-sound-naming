# UCS Sound Naming —— 音效命名翻译 Skill 介绍

> 一个为音效设计师与媒体归档人员打造的 AI 技能（Skill）：根据 **UCS（Universal Category System）8.2.1** 标准，把任意音效描述或文件名批量转换为规范的中英双语命名清单。

---

## 一、这个 Skill 是什么

`ucs-sound-naming` 是一个遵循标准 Agent Skill 规范的技能包（一个 `SKILL.md` + 配套参考资料目录），挂在支持 Skill 的 AI 客户端（如 WorkBuddy、豆包等）下即可使用。

它的核心能力一句话概括：

> **输入一段音效描述（中文/英文）或一个音效文件名，输出符合 UCS 8.2.1 标准的规范命名，格式为：【（中文分类）中文关键词...】`CatID_FXName_CreatorID_SourceID`（FXName 用空格分隔单词）。**

它把"查 UCS 分类表 → 匹配 CatID → 生成英文官方命名 → 翻译中文关键词 → 输出双列清单"这一整套专业流程，固化成了 AI 可重复执行的步骤，**无需人工翻阅分类表**。

## 二、能做什么

| 场景 | 输入 | 输出 |
|---|---|---|
| 为音效命名 | 「异形攻击的声音」 | `【（生物_怪兽）异形，攻击】CREAMnstr_Alien Attack_B00M_01.wav` |
| 翻译已有 UCS 命名 | `MAGElem_Fire,Burning,Medium,01,F#m,...` | `【（魔法_元素）火焰，中等，燃烧，01，F#m】MAGElem_Fire Burning Medium 01 F#m_B00M.wav` |
| 批量文件清单 | 数百个 wav 文件名/描述列表 | 双列 .txt 命名清单（`原文件名<TAB>翻译后文件名`，按需生成） |
| 模糊描述 | 「户外录的风声」 | 提供多个候选 CatID 并说明各自适用理由 |

典型应用：为 300G 级别的音效库批量生成规范化命名与中文归档清单。

## 三、工作流程

Skill 内置 6 步工作流，AI 按此执行：

1. **理解描述** —— 读取用户提供的音效描述（中英文均可）。
2. **匹配 CatID** —— 从内置完整对照表 `references/ucs-zh-en.tsv`（753 条 UCS 8.2.1 记录）中匹配最合适的 CatID；**只使用表中存在的 CatID，绝不猜测或创造**。
3. **生成英文命名** —— 按 UCS 官方格式 `CatID_FXName_CreatorID_SourceID` 生成（FXName 用空格分隔单词；文件编号置于关键词后、调性前；CreatorID 取自库元数据，SourceID 有则追加、无则省略）。
4. **生成中文翻译** —— 在英文文件名前添加 `【（中文分类）中文关键词1，中文关键词2，...】`（中文逗号分隔），紧贴英文部分、无空格。
5. **输出映射并确认归档** —— 先展示双列映射（`原文件名<TAB>翻译后文件名`），**询问是否写入 .txt 清单**；可配置 `listFile.enabled=false` 默认关闭以省 token。
6. **写工作日志** —— 追加到 `<UCS_ROOT>/日志/<Agent>_YYYY-MM-DD.md`。

## 四、核心规则（要点）

- **严格 UCS 8.2.1**：CatID 必须来自对照表，大小写不可更改。
- **Foley 限制**：FOLY* 目录仅用于对画面表演的官方干净拟音；户外、非正式、自录素材应归入 FOOTSTEPS（FEET*）或 OBJECT（OBJ*）类。
- **模糊描述**：提供多个可能 CatID 并说明理由；信息不足先提问。
- **已命名文件**：可直接进入翻译步骤，英文部分（含 CreatorID、SourceID）不改。
- **英文命名**：官方格式 `CatID_FXName_CreatorID_SourceID`，FXName 用空格分隔单词；不再使用逗号分隔关键词列表。
- **编号位置**：原文件开头编号置于关键词序列末尾、调性之前（中英文一致）。
- **固定译法**：whoosh → 呼啸；调式（如 F#m）也译入中文关键词内。
- **中文关键词 2-5 个**（推荐值；英文为 UCS 官方命名时中英文数量跟随英文）。
- **文件名总长不设限**（官方 FXName≤25 仅约束 FXName 块）。
- **去重**：文件名不出现重复词语；重名依次追加编号。
- **风格**：简洁、专业、术语准确，面向音效设计师与媒体归档人员。

## 六、输出格式与命名规范

- **双列 .txt 清单**：`原文件名<TAB>翻译后文件名`，TAB 分隔；清单文件命名 `UCS_命名清单_<Agent>_<库名>.txt`。
- **英文侧**：UCS 官方格式 `CatID_FXName_CreatorID_SourceID`。示例：
  `MAGElem_Fire Burning Medium 09 F#m_B00M.wav`
  - `MAGElem` = CatID；`Fire Burning Medium 09 F#m` = FXName（空格分隔单词，编号在关键词后、调性前）；`B00M` = CreatorID；SourceID 有则追加、无则省略。
- **中文侧**：`【（魔法_元素）火焰，中等，燃烧，09，F#m】` 紧贴英文文件名、无空格。
- **清单按需生成**：默认生成，输出前询问用户；`listFile.enabled=false` 可默认关闭省 token。

## 七、成本参考

按所用模型 API 计费。以 DeepSeek-chat 为例，批量处理 300G 音效库（约 6 万个文件）：

- **最便宜 ≈ 7 元**（空闲时段 + 输入缓存命中）
- **最贵 ≈ 14 元**（高峰时段 + 缓存未命中，约为最便宜的 2 倍）
- 费用主要取决于文件数量与是否命中输入缓存，与音频体积无直接关系。

## 八、在哪些免费平台可用

本 Skill 是标准 Agent Skill 目录（`SKILL.md` + `references/`），**整个文件夹可直接拖入**以下平台使用：

| 平台 | 推荐度 | 说明 |
|---|---|---|
| **豆包** | ⭐ 推荐 | 免费使用，支持拖入 skill 文件夹，中文理解好，适合直接对话式命名 |
| **WorkBuddy** | 👍 可用 | 可领取平台额度，适合体验与轻量使用 |
| **DeepSeek** | ⚠️ 不推荐 | 上下文空间较小，拖入含完整对照表的文件夹（753 条 + 73KB tsv）容易撑爆上下文；仅适合直接对话提问 |

> 提示：`references/ucs-zh-en.tsv` 对照表约 73KB，占上下文较大。小上下文平台建议只拖入 `SKILL.md` + `references/naming-rules.md`，对照表按需单独粘贴或分批查询。

## 九、相比 AI 翻译软件的优势

| 对比项 | 本 Skill | 一般 AI 翻译软件 |
|---|---|---|
| **命名规则可修改** | ✅ 规则全部是文本文件，可随时增改（Foley 限制、去重、编号规则等） | ❌ 固定模板，无法定制 |
| **命名自由度** | ✅ 关键词数量、顺序、调式、编号策略均可自定义 | ❌ 只能按软件预设格式输出 |
| **中文音效 → 中英双语 UCS 规范** | ✅ 中文描述可映射为官方 CatID，输出「【中文】CatID_FXName」双语规范名 | ❌ 通常只会直译文字，不产出 UCS 分类标识 |
| **标准依据** | ✅ 内置 UCS 8.2.1 完整对照表（753 条），CatID 不猜测、不创造 | ❌ 无分类表，命名随意 |
| **口径一致性** | ✅ `known-conflicts.md` 固化裁决，多人协作输出统一 | ❌ 每次输出可能不一致 |
| **批量与成本** | ✅ 整库生成双列 .txt 清单，可直接喂给重命名工具 | ❌ 逐条翻译，成本随条数线性增加 |
| **跨平台迁移** | ✅ 标准 Skill 格式，可迁移到多个 AI 客户端 | ❌ 数据锁在单一软件内 |

## 十、如何安装使用

1. 将本目录（或 `ucs-sound-naming.zip` 解压后的目录）放入 AI 客户端的 skills / agent-skills 目录。
2. 按 `install.md` 完成首次部署：建「命名清单 / 日志 / 规则更新」三目录 → 配置环境变量 `UCS_ROOT` → 复制 `ucs-config.local.json` 按习惯调整 → 自检。
3. 在对话中直接描述音效（中文/英文），或粘贴文件名清单，例如：
   - 「给这些生物音效命名：异形攻击、飞龙平静、疣猪死亡」
   - 「把这个列表翻译成 UCS 命名清单：`bellow_large_01.wav` ...」
4. 获得双列 .txt 命名清单，确认后即可用于批量重命名。
