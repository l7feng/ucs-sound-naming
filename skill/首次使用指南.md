# ucs-sound-naming 首次使用指南

> 面向第一次使用本 skill 的用户/Agent。部署步骤见 `install.md`，本文件回答「我要准备什么、我要提供什么、我会得到什么」。

---

## 一、这是什么

一个让 AI 按 **UCS 8.2.1 国际标准**为音效文件生成规范命名清单的 skill。输入音效描述或文件，输出「原文件名 → 翻译后文件名」的双列映射清单，可一键批量重命名。

## 二、首次使用前需要准备（一次性）

| 项目 | 说明 | 位置 |
|---|---|---|
| ① skill 本体 | 解压 `ucs-sound-naming.zip` 到 Agent 的 skill 目录 | Agent 可识别即可 |
| ② 工作根目录 | 含「命名清单 / 日志 / 规则更新」三个子目录 | 自选，建议如 `D:\Ai_Project\UCS` |
| ③ 环境变量 `UCS_ROOT` | 指向工作根目录，Agent 每次自动定位 | 设一次长期有效（见 install.md 第 2 步） |
| ④ 本地习惯配置 | 复制 `ucs-config.default.json` → 重命名 `ucs-config.local.json` 按需调整 | 放 `<UCS_ROOT>/规则更新/` |
| ⑤ 对照表与矛盾裁决 | `references/ucs-zh-en.tsv`、`references/known-conflicts.md`，skill 自带 | 已内置，无需另备 |

> 红线（不可改）：UCS 对照表、矛盾裁决、CatID 分类本体。习惯只能改展示格式，不能改分类本体。

## 三、首次对话时，你需要提供给 AI 的信息

1. **音效库名称**（如 `BOOM_Canyons`）——决定清单文件名
2. **音效描述或文件**：中文描述、英文文件名，或直接给出文件目录
3. **库名/编号规则**（如有）：如 CreatorID、SourceID、文件名前缀含义
4. **你的习惯偏好**（如想改配置，提前告知）

## 四、首次对话模板（可直接复制）

```
使用 ucs-sound-naming skill。
音效库：<库名>
源路径：<文件目录或文件名列表>
源 ID / 编号规则：<如有>
请生成命名清单并输出到工作根目录。
```

## 五、AI 会输出什么（产出物）

| 产出 | 位置 | 命名 |
|---|---|---|
| 命名清单（双列 .txt） | `<UCS_ROOT>/命名清单/` | `UCS_命名清单_<Agent>_<库名>.txt` |
| 工作日志 | `<UCS_ROOT>/日志/` | `<Agent>_YYYY-MM-DD.md` |
| （可选）规则文档 | `<UCS_ROOT>/规则更新/` | `<文档名>_v<X>.<Y>.md` |

## 六、首次自检清单

- [ ] 三目录已建立（命名清单 / 日志 / 规则更新）
- [ ] 环境变量 `UCS_ROOT` 已配置，或已告知 AI 根目录
- [ ] `ucs-config.local.json` 已按习惯调整
- [ ] 用第四节的模板试跑一次，确认清单正确输出到「命名清单」目录

## 七、常见疑问

**Q：我不知道 UCS 是什么，影响使用吗？**
不影响。AI 内置对照表，你只需提供音效描述/文件，分类和命名由 AI 完成。

**Q：我只有中文描述，没有原文件？**
可以。AI 会按 UCS 生成完整命名（含英文部分），清单第二列即翻译后文件名。

**Q：多台电脑/多个 Agent 会不会互相覆盖？**
不会。清单和日志文件名都带 Agent 标识（`<Agent>`），物理隔离。

**Q：音效库自带的说明文件（txt/pdf/jpg 等）会怎样？**
会被删除，不进清单、不重命名。删除前会先预览完整删除清单并请你确认；无法确认来源的文件会标注「待确认」暂不删。

**Q：命名清单一定会生成 .txt 文件吗？**
默认会，但 AI 会先展示双列映射并**询问是否写入** .txt。若想默认不写（省 token），可在 `ucs-config.local.json` 设 `listFile.enabled=false`，需要时随时可重新生成。
